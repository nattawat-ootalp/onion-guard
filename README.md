# OnionGuard — ระบบ AI คัดกรองเชื้อราบนหอมแดงด้วยแสง UV 365 นาโนเมตร

คัดกรอง "ความผิดปกติที่สัมพันธ์กับเชื้อรา" บนหอมแดง จากภาพถ่ายใต้แสง UV 365nm
ด้วยการสกัดฟีเจอร์ + Random Forest แล้วแสดงผลบนเว็บ

> **สถานะ: ยังใช้ข้อมูลจำลอง** — โมเดลปัจจุบันฝึกจาก mock data ล้วน
> ตัวเลขความแม่นยำทั้งหมด**ยังไม่มีความหมาย** ต้องเก็บภาพจริง + ผล CompactDry YM
> แล้วเทรนใหม่ก่อน ดูหัวข้อ "ขั้นตอนต่อไป"

## วิธีเริ่มใช้

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/python src/generate_mock_data.py    # สร้างภาพจำลอง (ไม่ได้เก็บใน repo)
.venv/bin/python web/app.py                   # เปิดเว็บที่ :5000
```

บน Raspberry Pi ใช้ `requirements-pi.txt` แทน (ตัด pandas/scipy/matplotlib ออก)

## การทำงาน

ถ่ายด้วยมือถือ (Pro mode ล็อก ISO/shutter/WB) → อัปโหลดผ่านเว็บ → เซิร์ฟเวอร์ประมวลผล
มือถือไม่ได้คำนวณอะไร เพราะโมเดลเป็น Python รันในเบราว์เซอร์ไม่ได้

```
อัปโหลด (JPEG / DNG)
  → Pillow/rawpy  อ่านไฟล์ + หมุนตาม EXIF
  → onion_detect  หาหัวหอม แล้วครอบ+ย่อให้อยู่กลางกรอบขนาดคงที่
  → predict       สกัด 23 ฟีเจอร์ (สี ความสว่าง พื้นผิว พื้นที่ผิดปกติ จุด/ปื้น NDFI)
  → RandomForest  ตัดสิน + วาดวงทับจุดที่เจอ
```

**ทำไมต้องครอบใหม่ทุกภาพ:** threshold ขนาด blob เป็นจำนวนพิกเซลตายตัว
ถ้าถ่ายใกล้/ไกลต่างกัน "จุดเล็ก" กับ "ปื้นใหญ่" จะหมายถึงคนละขนาดจริง
วัดจากภาพจริงสองใบ ตำแหน่งต่างกัน 28% ขนาดต่างกัน 14%

## โครงสร้าง

| ไฟล์ | หน้าที่ |
|---|---|
| `config.json` | พารามิเตอร์ทั้งหมด (ROI, threshold, กล้อง, ลำดับการถ่าย) |
| `src/generate_mock_data.py` | สร้างภาพจำลอง |
| `src/onion_detect.py` | หาหัวหอม + ครอบให้ขนาดคงที่ |
| `src/extract_features.py` | สกัดฟีเจอร์ → `data/features.csv` |
| `src/eda.py` | สำรวจข้อมูล + baseline ROC |
| `src/train.py` | เทรน + ตรวจสอบไขว้ StratifiedGroupKFold |
| `src/train_final.py` | วิเคราะห์ที่ผิด + เทรนสุดท้าย → `models/` |
| `src/predict.py` | ทำนาย 1 หัว (พึ่ง numpy/cv2/joblib เท่านั้น) |
| `web/app.py` | Flask |
| `web/data_source.py` | ชั้นข้อมูล — เปลี่ยนไป Supabase ทีหลังได้ที่นี่ |
| `src/camera.py` ฯลฯ | โค้ดกล้อง USB (ไม่ได้ใช้แล้วหลังเปลี่ยนมาถ่ายด้วยมือถือ) |

## ระบบเตือนเมื่อผลเชื่อไม่ได้

ออกแบบให้บอกตรง ๆ เมื่อผลไม่น่าเชื่อถือ แทนที่จะโชว์ตัวเลขสวย ๆ เฉย ๆ

- **นอกช่วงข้อมูลฝึก** — Random Forest ประมาณค่านอกช่วงไม่ได้ ภาพจริงเคยให้ 71 จุด
  ขณะที่ตอนฝึกสูงสุด 18 จุด ระบบจะเตือนแทนที่จะตอบมั่ว
- **ผลก้ำกึ่ง** — เมื่อความน่าจะเป็นอยู่ระหว่าง 0.5 กับเกณฑ์ตัดสิน
- **การจัดกรอบมีปัญหา** — หาหัวหอมไม่เจอ / ชนขอบภาพ / ต้องเติมขอบดำมาก
- **ค่ากล้องไม่คงที่** — เทียบ EXIF และความสว่างพื้นหลังระหว่างมุม

## ขั้นตอนต่อไป

1. **เก็บภาพจริง** — บวก 30 / ลบ 30 โดยกลุ่มลบ**ต้องมีตัวยาก** (เปลือกถลอก คราบ ช้ำ)
   ไม่ใช่หอมสวยล้วน เพราะขอบเปลือกฉีกเรืองแสงได้และถูกจับเป็น blob
2. ป้ายกำกับต้องมาจาก **CompactDry YM เท่านั้น** ไม่ใช่จากที่ตาเห็นว่าเรืองแสง
3. **ลดฟีเจอร์เหลือ 6–10 ตัว** — 23 ฟีเจอร์ต่อ 60 ตัวอย่าง = 2.6 ตัวอย่าง/ฟีเจอร์ เสี่ยง overfit
4. **แก้สมมติฐาน "ปื้นใหญ่"** — mock ถือว่าปื้นใหญ่ = คราบ = ลบ แต่ของจริงคือเชื้อลุกลาม = บวก
5. รายงานผลเป็นช่วงความเชื่อมั่น — ที่ n=60 วัดได้ 90% หมายถึงค่าจริง 82–98%

## ข้อจำกัดที่ยังค้าง

- สูตร NDFI เป็นนิยามที่เขียนขึ้นเอง ยังไม่ได้เทียบกับเล่มรายงาน
- ยังไม่ได้ทำ dark-frame subtraction (ถ่ายเฟรมมืดได้แต่ยังไม่เอาไปใช้)
- iPhone/HEIC ยังไม่รองรับ (ต้องตั้งมือถือให้บันทึกเป็น JPEG หรือติดตั้ง pillow-heif)
